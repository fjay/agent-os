# Agent 知识更新规则

> 更新日期: 2026-05-18
> 适用项目: AgentOS（`/root/code/agent-os`）

---

## 一、原则

### 1.1 只描述当前行为

所有知识文件必须反映代码的**当前状态**，不记录历史变更、已删除的功能或计划中的改动。

- 正确: "所有 API 路由均无认证"
- 错误: "之前有认证，后来移除了"

### 1.2 不追加历史

知识文件不维护变更日志。每次更新是全量替换，不是增量追加。

- 正确: 直接修改文档中过时的描述
- 错误: 在文档末尾追加 "2026-05-18 更新: ..."

### 1.3 结论绑定代码路径

所有事实性描述必须标注代码路径（`文件:行号`），便于验证。

- 正确: "命令执行超时 10 秒（`app/api/exec/route.ts:8`）"
- 错误: "命令执行有超时限制"

### 1.4 不生成空模板

如果某个模块没有相关信息（如没有自定义 Error 类），直接说明"不存在"，不创建空表格。

### 1.5 基于证据更新

更新知识必须基于代码搜索结果，不基于假设或记忆。

## 二、必须更新的场景

以下场景发生变更时，必须更新对应的知识文件：

### 2.1 代码结构变更

| 变更类型                     | 影响的知识文件               | 说明                        |
| ---------------------------- | ---------------------------- | --------------------------- |
| 新增/删除 `lib/` 下的模块    | 仓库结构、架构、代码搜索指南 | 核心业务逻辑变更            |
| 新增/删除 `app/api/` 路由    | 仓库结构、架构、安全分析     | API 端点变更                |
| 新增/删除 `components/` 组件 | 仓库结构                     | UI 组件变更                 |
| 新增/删除 `data/` 模块       | 仓库结构、架构               | 数据层变更                  |
| 数据库 Schema 变更           | 架构（数据库表结构）         | `lib/db/schema.ts` 修改     |
| 新增数据库迁移               | 日志与错误处理               | `lib/db/migrations.ts` 修改 |

### 2.2 安全相关变更

| 变更类型         | 影响的知识文件       | 说明                       |
| ---------------- | -------------------- | -------------------------- |
| 新增认证机制     | 权限模型、敏感操作   | 从"无认证"改为实际认证方式 |
| 修复命令注入     | 敏感操作、Shell 策略 | 从 `exec` 改为 `execFile`  |
| 新增路径验证     | 权限模型、敏感操作   | 文件操作增加路径白名单     |
| 新增 CORS/安全头 | 权限模型             | HTTP 安全策略变更          |
| 新增 API 端点    | 敏感操作             | 评估新端点的安全风险       |

### 2.3 日志和错误处理变更

| 变更类型         | 影响的知识文件               | 说明                          |
| ---------------- | ---------------------------- | ----------------------------- |
| 新增日志关键词   | 日志与错误处理、告警诊断指南 | 新的 `console.error/log` 调用 |
| 修改错误消息格式 | 日志与错误处理               | 日志模式变更                  |

### 2.4 核心模块行为变更

| 变更类型                          | 影响的知识文件           |
| --------------------------------- | ------------------------ |

## 三、通常不需要更新的场景

### 3.1 UI 样式变更

CSS、主题配置（`lib/theme-config.ts`、`lib/terminal-themes.ts`、`styles/`）的纯样式调整不影响功能知识。

### 3.2 依赖版本升级

`package.json` 中的依赖版本更新（如 Next.js 16.1 → 16.2），除非引入了破坏性 API 变更。

### 3.3 前端状态管理微调

`stores/`、`contexts/` 中的状态管理细节调整（如新增一个 UI 状态字段），不影响核心业务逻辑。

### 3.4 文档/注释更新

代码注释和 `docs/` 下的纯文本文档更新不影响代码行为知识。

### 3.5 构建配置微调

`next.config.ts`、`tsconfig.json`、`.eslintrc` 等构建工具配置的微调，除非影响运行时行为（如新增 CORS 配置需要更新安全知识）。

### 3.6 测试文件变更

测试文件的增删改不影响生产代码行为。

### 3.7 PWA/Service Worker 配置

`app/sw.ts`、`app/serwist-provider.ts`、`public/manifest.json` 的微调。

### 3.8 Tauri 桌面端配置

`src-tauri/` 下的配置和 Rust 代码微调，除非影响与 Node.js 服务器的交互方式。

---

## 四、更新流程

1. 确定变更范围（哪个模块、哪些文件）
2. 使用 `rg` 搜索变更后的代码状态
3. 阅读相关文件，确认行为变化
4. 更新对应知识文件中的相关章节（全量替换，不追加）
5. 验证更新后的描述与代码一致
